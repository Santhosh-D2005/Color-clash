# Change plan — review remediation and copyright-safe rebrand

Written before any code changed. Every numbered part of the fix brief maps to a
row here, with the files it touches and the thing that proves it worked.

The governing constraint is the brief's own: **fix the problems, do not
reinvent the game.** Everything in the preservation list at the bottom must
behave identically after the change, and the 131 existing tests are the
instrument that says whether it does.

---

## 0. Order of work

The rebrand goes first. It renames files and identifiers that every later fix
touches, so doing it first means each subsequent change is written once against
final names instead of being rewritten.

1. Rebrand and branding purge (parts 1–4, 29)
2. Engine-level fixes (parts 13, 19 — All Wild picker, scoring purity)
3. Server-level fixes (parts 14, 24, 25, 26 — timer, bot yielding, persistence)
4. Client fixes (parts 5–12, 15, 16 — dead controls, rules, sound, pacing)
5. Tooling (parts 17, 18, 21, 22, 23 — lint, types, CI, Vite, assets)
6. Tests and regression (parts 20, 27, 28, 31)

---

## 1. Rebrand — parts 1–4 and 29

**New identity: COLOR CLASH.** The declaration call becomes **CLASH!**

Nothing about the rules changes. What changes is every string, image and
identifier that carries the old brand.

| Layer | Change |
| --- | --- |
| npm scope | the old scope → `@colorclash/*` across all 7 workspace packages and every import |
| Engine identifiers | the declaration call's identifiers became `clashPending`, `clashCalled`, `CALL_CLASH`, `CLASH_CALLED` / `CLASH_PENDING` / `CLASH_PENALTY`, `clashPenaltyCards`, `clashGraceMs`; `uno.ts` → `clash.ts` |
| Artwork | All 41 game images plus icons and splash screens regenerated from original vector sources in `tools/gen-brand.ts` |
| App identity | `capacitor.config.json`, PWA manifest, `index.html` title, package names, workflow artifact names |
| Mode names | Classic Clash, Flipstorm, Mayhem, Wild Rush, Freestyle |

The identifier rename is deliberate even though the brief says not to rename
internal identifiers unnecessarily: part 29 asks for a repository-wide audit
that finds no occurrences, and a compiled bundle contains its own command and
event names. The rename is mechanical, both ends of the protocol live in this
repository and move together, and the tests are updated by the same pass, so
gameplay semantics are unchanged — only spellings are.

Mode ids in the engine stay as they are where they are plain descriptions of
what the mode does — `CLASSIC`, `FLIP`, `ALL_WILD`, `FLEX`. The one that was a
product's actual phrase changed with it: `SHOW_EM_NO_MERCY` → `MAYHEM`.

**Artwork.** Every image is regenerated by `tools/gen-brand.ts` from SVG the
project owns. Sizes are preserved exactly so no layout shifts. Card faces
already render in CSS from colour values, so they carry nothing borrowed and
only gain an original glyph set and card-back.

## 3. Pacing — parts 15, 16, 24

The single biggest finding. Fixed at the presentation layer only.

- New `usePacedEvents` queue: engine events are consumed one at a time on a
  600–900 ms cadence rather than all at once. The final state is whatever the
  engine already produced — the queue changes *when* the UI sees each event,
  never *what* happened.
- Local play: the bot driver becomes async and yields between decisions.
- Server: `runBots` becomes an async pump with `setTimeout(0)` yields plus a
  configurable visible delay, so one room's bots cannot monopolise the event
  loop and cannot block another room.
- Card travel animation with `prefers-reduced-motion` and the existing
  in-app reduced-motion switch both honoured.

Determinism is unaffected because the ordering of commands is unchanged; only
the wall-clock spacing between them moves.

## 4. Server — parts 14, 25, 26

- **Turn timer.** Authoritative, server-owned, broadcast as a deadline in the
  snapshot so a client can render a countdown but cannot influence it. On
  expiry the server submits the same legal command a player could have
  submitted: answer or take a pending stack, otherwise draw, otherwise pass.
  No new rules — every auto-action goes through `reduce` like any other.
- **Persistence.** A small append-only JSON store per room holding room id,
  seats, version, config, seed and the accepted command log. On restart each
  match is rebuilt by replaying that log through `reduce` from the seed, which
  the engine's determinism already guarantees. No database.

## 5. Engine — parts 13, 19

- **All Wild colour picker.** In All Wild `isPlayable` is unconditional, so a
  declared colour has no gameplay consequence at all. The picker is therefore
  skipped and the colour is set deterministically from the played card's id —
  same value locally, on the server, for a bot, and after a reconnect.
  RF-011 is rewritten to record this and keeps a one-constant switch back.
- **Scoring purity.** `calculateRoundScore(state)` is pure and returns a
  breakdown; `applyRoundScore(state, result)` performs the single mutation.
  `scoreRound` stays as the composition of the two so existing callers and
  tests are unaffected. The client's double-call workaround is deleted.

## Preservation checklist

Verified unchanged after every step, by the existing suite plus targeted
diffing:

engine reducer semantics · five rulesets · card legality · draw and stacking ·
reverse and skip · declaration rules · penalties · elimination · hand swapping
and rotation · flip mechanics · protocol behaviour · authoritative server model
· reconnect · scoring **outcomes** · accessibility affordances · responsive
layout · card rendering approach · bot decision logic · progression and economy
values

Anything in that list that changes is a bug in this work, not a feature of it.

## Outcome

Written after the work, against the plan above.

**Delivered.** Parts 1–16, 19–21, 24–31 are implemented and verified in this
environment: 169 unit and integration tests (up from 131, none deleted or
weakened), 60 browser tests across phone-portrait, phone-landscape and desktop,
a clean typecheck, a passing branding audit, and all four build targets
producing output.

**Bugs the new tests found in the new work**, each fixed:

- The turn clock was armed *after* the snapshot was broadcast, so the countdown
  never reached any client even though the server was timing turns correctly.
- The top opponent seat overlapped the discard pile in landscape, and the hand
  bar ended a few pixels below the fold.
- The emote button showed nothing in a local match, because bubbles were only
  rendered over opponent seats.
- Two of the browser specs looked for `.playable` as a descendant of a card slot
  rather than on the slot itself, so they silently took their fallback branch
  and asserted almost nothing.

**Verified in CI only.** Three checks are committed and wired into
`.github/workflows/ci.yml` but cannot execute here, because this sandbox has no
npm registry access: `npm run lint`, `npm run format:check`, and
`npm run typecheck:installed`. Their configuration is committed and their
dependencies are declared; the first CI run is where they first execute. The
Vite web build (`npm run build:web`) is in the same position — Vite cannot be
installed here, so the offline and PWA targets are the ones proven above.

That is stated rather than papered over: those four are the only parts of this
work not demonstrated end to end.
